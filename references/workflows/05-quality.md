# 05 · 分层质量验收

## 三种独立结论

1. 文件合格：实际编码文件可打开、数量正确、画布/体积/帧数/时长/循环合格、有可见前景。
2. 视觉合格：角色、文字、动作与边缘经查看和完整播放检查。
3. 平台可投稿：当前账号入口规则已核验且所需物料齐备。

`studio.py verify` 验文件；`visual-review.json` 记录视觉结论并与文件 SHA-256 绑定；平台在独立 evidence 记录。任何一层不能冒充另一层。

## 视觉清单（每条）

- identity：轮廓、配色、服装/脸/眼镜与母版一致；允许的夸张有依据。
- anatomy：肢体与道具没有增减、穿透、左右翻转。
- caption：准确、可读，不挡脸/手/主道具；字体与角色匹配，全套遵循选定排版模式；实际使用大小可读，有意文字变化符合轨迹、幅度与阅读时长。
- motion：角色真实表演，动作链合理，不是无关姿态轮播；检查眼睑进入/退出姿态、闭眼频率与动作峰值停留，按[面部与节拍](../motion/eye-timing.md)验收。
- loop：至少播放两个循环，接点自然、峰值有阅读时间。
- edges：浅/深背景无明显色边、残幕、棋盘纹理、裁断线。

先看接触表，再看 GIF/WebP 播放。接触表只能验相邻姿态，不能替代播放；若环境不支持播放，可生成本地 HTML 播放页/视频供检查，未实际检查前 loop、motion 不能填 pass。

## 主体稳定与动作密度

操作方法、适用条件和故障记录见 [动态稳位](../technical/motion-stability.md)。修复源帧后必须重新编码并绑定新的文件哈希。

每条动作指定可保持稳定的局部锚点，例如躯干中心、坐姿支点或固定道具；头部本身参与动作时不可锁头抵消表演。逐帧对比锚点位置、主体比例与静态文字基线，区分有意重心变化和无关漂移。共同画布与共同缩放只能保持源帧几何，不能保证生成角色已对齐。

主体与文字不应依赖整图包围盒共同居中：挥手会改变包围盒但不应带动躯干，文字重画也会改变字宽。优先固定文字层与主体锚点，再检查动作变化。几何稳位不能修复换脸、比例变形或姿势不连贯，这些须重生成或定向编辑。

报告实际独立姿势数量、各帧停留与总时长。八姿势播放1.6秒仍只有约每秒五个姿势，增加容器帧率或重复帧不会增加动作细节。需要平滑动作时生成更密集、连贯的真实姿势或使用可用视频路线；未实际执行插帧不得声称已补间。稳定性和动作密度经样张验收后再批量扩套。

visual-review 模板的结果默认 pending。审核人是 Agent 或用户，记录方法与证据路径；不得脚本自动填全 pass。每个交付文件的哈希均需匹配，重新编码或改字后旧结论失效。无字时 caption 可记 pass 并注明无字；静态时 motion/loop 可记 pass 并注明不适用。

## 返工规则

FAIL → 具体故障 → 影响源文件 → 单项修复 → 新版本 → 重验。两轮失败后停止该项、换路线或报告，成功项可保留，但整套状态为 partial。想提前交付部分时明确数量并保持未完成清单，不能把失败项静默移出 pack。

评价不得用臆造精确分数。机器像素差、边界接触和重复帧是辅助信号；只靠这些不能判艺术动作。真正角色漂移需要看母版与帧。
