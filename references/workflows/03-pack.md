# 03 · 套系策划与文案

一条表情要回答“何时、对谁、替代哪句话”，不能只叫“开心/生气”。同一主题覆盖回应、推进、求助、拒绝、共情、庆祝等角色；同意图可以有强弱变化，但不能全套只换字。

## pack.json 记录

每个 item 有稳定 id、name（简短中文表情名）、meaning（含义词）、intent、caption、action、motion_key、frame_beats、durations_ms、files。name 用于成品文件命名；meaning 概括聊天意图或情绪，可与 caption 相同，也可用更清晰的短语。无字表情也要准备 name 与 meaning。静态不需要 frame_beats；动态要求至少两个有意义姿势，数量与 durations 一致。模板建议八帧不是硬限制，可调整网格和时长。

全套 `pack.typography` 保存排版模式、字体、调色板、描边、字号层级和安全区。每条可用 `caption_layout` 记录锚点/换行，用 `text_motion` 记录有意的变换轨迹；这些项目记录与成品一起保留，不把方案对照当成已定稿模式。

台词优先短口语，含义词/搜索标签另存。制作前读一遍全文避免错字、冷僻字、套内重复。无字也应能从姿势看出情绪。文字与角色一起规划，读取 [文字设计](../styles/typography.md)，默认随构图排字，按各条动作留白选择上方、侧边、斜侧等位置；用户明确要求时才选统一底部模式。检查整个动作周期的文字与脸、手、主道具避让，并记录有意的文字变化。模型文字有误时以图像编辑修正，或在用户授权的文字合成路线加入文字层；不擅自用代码重绘角色。

## 套系结构示例

| 打工仔 | 意图 | 一个主动作 |
|---|---|---|
| 收到 | 回应任务 | 抬手敬礼、短点头 |
| 正在赶工 | 报进度 | 手指交替敲键盘 |
| 又要改啊 | 对修改要求的无奈 | 推眼镜、垂眉 |
| 偷偷摸鱼 | 分享轻松状态 | 瞟旁边、藏手机 |
| 电量不足 | 疲惫求缓冲 | 耷拉眼皮、提咖啡 |
| 下班跑路 | 结束工作 | 手脚完整跑步周期 |

| 发财系列 | 意图 | 一个主动作 |
|---|---|---|
| 发大财 | 祝福/期待 | 举元宝、抱紧 |
| 赚大钱 | 努力挣钱 | 分清三枚金币、数完放回 |
| 财运来 | 迎接好运 | 小手招财 |
| 订单爆了 | 分享订单喜悦 | 托包裹举起 |
| 到账啦 | 收款庆祝 | 看手机、握拳 |
| 一起发财 | 社交祝福 | 抱拳起落 |

这些是可修改的主题建议，不是事实收益、理财保证或固定模板。用户指定数量要保留，不能为了凑九宫格擅自删减/扩充。九宫格只是展示布局，独立交付数量以 pack 为准。

## 套内表演差异

先用关键姿态接触表检查：遮住文字后，能否凭神态、身体姿势、视线与动作意图区分各条。若多数条目都是同一正面笑脸加不同道具，先调整情绪和动作构图，不以换物件或换台词代替表演。给主要条目明确的情绪强弱、眼眉嘴变化、躯干姿态与动作幅度；不强制每条都夸张。

角色一致性保持识别特征、线条、配色和轮廓结构，不等于全套固定表情或禁止侧身、躺卧、鞠躬与有意挤压伸展。稳位只校正无关漂移；不要锁住所有头部和身体运动，也不要为避免眨眼问题让全套永远睁眼微笑。表情变化需要进入和退出过渡帧。

## 样张选择

最先做一个同时覆盖角色、道具和动作难点的样张，完成帧表→编码→播放。样张仅好看但不能动不算通过。用户要先看样就等待反馈；用户已要整套则内部过检后继续下一批。
