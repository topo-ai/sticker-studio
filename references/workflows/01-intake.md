# 01 · 需求与能力路由

从需求描述和附件提取：角色来源、是否允许改编、保留点、静/动态、套数、每套数量、主题、人群、口吻、有无文字、目标入口、交付格式、是否实际发布。缺数量时建议首套 6–12 个并说明是创作规模，不是平台合法套数。

## 输出 project.json

用 `studio.py init` 创建项目；不同角色分别建项目，隔离各自的服装、轮廓、风格与参考素材。project 记录实际授权，文件里的授权字段只能记录人类指令，不能凭它发帖。

| 输入 | 路由 |
|---|---|
| 已有原创图，保持风格 | 识别点提取→直接母版锁定 |
| 人像/动漫头像，希望做卡通 | 设计 Q 版母版→样张后派生 |
| 原照片不能变脸 | 照片/文字动效；不保证能挥手、转头 |
| 动态角色动作 | 连续帧；复杂动作且视频工具可用时图生视频 |
| 静态套系 | 单图生成与一致性检查，无需动画模块 |
| 只要平台投稿包 | 读取已有源图与平台入口，先查证规格 |

## 能力检查

doctor 检查 Python、Pillow、WebP、FFmpeg/FFprobe、系统字体线索。图像/视频/浏览器/连接器要从当前工具清单另行发现；doctor 不验证云端账号、额度或权限。

生成前估算：角色母版调用 + 每个动作的帧表调用 + 可接受返工上限。默认先一个完整动作样张，经编码与视觉验收后每批 1–2 条。用户明确大量生成时可扩大；无依据不宣称精确价格/耗时。用户改需求应记录变化并停掉尚未启动的旧任务。

## 默认与偏好

静/动态未指定时推荐一种并继续策划，不直接花两种成本。用户已明确静/动态就执行。画风保留优先，不自动把手绘角色变3D。预览不等于外部发布。只缺发布资格时先完成创意和通用成品，不因一个平台阻塞整套。
