# 06 · 交付、投稿与复盘

## 通用交付契约

pack 中每个 ID 的必需格式必须存在并通过文件检查；项目 mode=animated 时至少 GIF 与动画 WebP，静态时 PNG。若用户明确只要一种格式，修改 required_formats 并记录用户选择，而非生成失败后偷偷删需求。

studio.py package 必须验证视觉审阅与当前文件匹配。ZIP 包含独立媒体、project/character/pack、视觉报告和文件清单，使用相对路径；不带原始隐私图片、临时视频帧、缓存、API密钥或 ZIP 自己。源素材另交只有用户要求时；不修改原图。

项目内保留 masters、frames、prompts 以便修改；交付包省略它们以减少混乱。失败项、告警和平台状态写明。已交付文件不覆盖，修改时使用新的版本路径。

## 文件命名与含义词

- 独立表情成品使用 `编号-中文表情名.扩展名`，例如 `01-收到.gif`、`04-偷偷摸鱼.webp`。编号按套内顺序从01开始，至少两位，超过99张时按总数统一补零；不将内部ID或纯数字作为最终交付文件名。
- 同一表情的 GIF、WebP、PNG、MP4 使用同一编号与中文名；平台、尺寸版本放在不同目录，避免同名覆盖。封面、横幅、图标等配套物料不占表情编号。
- 中文名优先采用画面短句；没有画面文字时按聊天意图命名。删除文件名非法字符和尾部空格/句点，不改变原意；保留稳定ID，更新 pack.items[].files、清单、预览与检查报告中的相对路径。
- 每套交付 `含义词.csv`（UTF-8 BOM，便于表格软件读取），列为 `id,file,caption,meaning`；同一表情有多个格式时每个文件一行，沿用同一含义词。pack.json 的每个 item 同时保存 name 与 meaning，便于续作和投稿。含义词是简短自然的中文意图或情绪，不机械堆砌标签。
- 打包前逐项核对编号、画面、中文名、含义词与实际文件一致；重排时同步更新。平台的含义词长度、必填性及分隔方式按当前表单验证，未知不虚构。清单随媒体一并交付；若内置打包器只包含已登记媒体和项目元数据，需将清单补入最终交付ZIP并重新检查归档。

## 平台包

读 [平台入口](../platforms/index.md)，按实际目标生成投稿图、缩略图、封面/横幅/图标、表单字段、版权材料待办。通用导出不自动算平台包；原始 GIF 不能代替视频展示版。不同平台文件来自高质量帧母版，不串联二次压缩。

## 实际发布

用户只要制作/策划时不提交。已明确“发布到此账号/入口”时依据现有授权执行，不重复确认；若目的账号或具体内容不明，完成所有可准备工作再问缺口。使用连接器/支持的浏览器，不杜撰上传 API。实名、验证码等用户完成，给精确卡点。

每个平台记录：目标账号、入口、内容版本、文件哈希、提交时间、回执 ID/链接、当前审核状态、驳回原文。提交超时先查历史，不能重按多次。审核通过且实际能访问后才写 live。不同平台分别结束；一个成功不掩盖另一个 blocked。

## 复盘与二期

用户提供/授权读取的曝光、添加/下载、使用、收藏、分享、评论和观察周期分开记录。不同指标不跨平台混算。识别使用场景缺口、哪种动作和短句最常用、是否用户不会取得原文件，再建议二期。没有数据先列采集口径，不编“爆款率”。未来监控仅在用户要求时设置。

## 完整套系清单

“整套成品”默认包含下表；用户明确只做某阶段、某格式或取消某物料时以用户范围为准。未知平台尺寸记录待核实，不将通用导出宣称为可投稿。

| 交付项 | 验收要求 |
|---|---|
| 独立表情 | 静态PNG；动态GIF与动态WebP，编号和含义词对应，真实动作与循环检查 |
| 预览与清单 | 整套播放预览、关键帧总览、含义词CSV、文件检查报告 |
| 头像 | 用于角色主页识别，单独命名；保留五官与标志配饰 |
| 专辑封面 | 按专辑入口要求设计，不将头像直接当封面 |
| 横幅 | 横向场景构图，避免拉伸方图；有无字与透明按入口要求 |
| 聊天图标 | 小尺寸下清晰，检查实际显示尺寸，不只验大图 |
| 赞赏引导 | 引导图与简短自愿支持文案，不夸大收益、不强迫赞赏 |
| 赞赏致谢 | 致谢图与感谢文案，和引导图风格一致但动作不同 |
| 投稿文案 | 名称、角色/专辑简介、版权署名待填项；不得虚构权属 |

为每项记录用途、文件、尺寸、格式、来源证据和状态；缺项显式列出，不以“完整包”掩盖遗漏。保留母版和原始生成记录，ZIP不带用户原照片与敏感资料。账号未开启赞赏时仍可交付备用物料，实际开启与投稿另依用户授权。
