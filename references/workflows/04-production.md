# 04 · 动作设计与生成

## 选择路线

静态：每条独立生图，复用角色母版与文字样式。
连续帧：每条动作用一个顺序帧表，减少逐帧独立生成造成的漂移。
图生视频：工具可用且动作复杂时，单角色单动作固定镜头，导出真实视频后抽帧。
局部分层：动作设计本身适合刚性小幅关节运动时，生成独立底稿与活动部件。它无法替代手指开合、连贯重心转移等逐帧表演；用户要求连续动作时保持连续帧或视频路线。见 [部件动画](../technical/cutout-animation.md)。
原图动效：只对用户选择的照片摇摆、文字弹跳等路线使用，不能替代角色表演。

## 动作计划

每条在 pack.json 中填写 frame_beats 和 durations_ms，形成：静止/建立情绪 → 预备 → 连续推进 → 峰值 → 停留 → 回落 → 接点。每帧写可观察的手/头/表情变化，不能每帧都写“开心”。姿态数量不足时补动作或改路线，不交无动作的循环。

样张建议 6–12 有意义帧、1.5–3 秒，用于起步而非平台规则。峰值比中间过渡停得久。GIF 时长为 10ms 整数倍，不声称任意 fps 都能精确编码。倒放仅用于可逆动作，数钱、收款、文字出现不能默认逆播。

涉及眼睛开合、笑眼或困倦表情时，先按[面部过渡与动作节拍](../motion/eye-timing.md)安排眼睑状态及进入/退出姿态，再生成帧表。

## 提示词编译

填完角色、风格、台词与动作后运行 `studio.py compile`，得到每条独立提示词。compile 负责拼接，实际图像/视频调用仍由 Agent 根据当前工具完成。先确认提示词文件存在，再调用生成工具。每条记录输入参考、工具、输出文件及候选版本。

参考模板：[静态](../prompts/static-sticker.md)、[帧表](../prompts/frame-sequence.md)、[视频](../prompts/image-to-video.md)、[修复](../prompts/targeted-repair.md)。调用时注明每张参考的职责。纯色抠像只能在工具输出不支持真 Alpha 且这条技术处理路线获允许时选用；幕色根据前景选，不盲目固定绿幕。

## 候选检查与批量

先检查格数与动作连续性，再切帧。人物换脸/眼镜漂移/道具突变/多手/网格错误属于候选失败，不靠裁切和减速掩盖。母版和样张通过后，一批 1–2 条，保存完成项；中断后根据文件继续，不整套重跑。

视频路线保存真实视频文件和输入图；用 `extract_video.py` 从指定有效区间抽帧，再跑公共 prepare/encode。没有视频能力则给接力包，状态 waiting_for_source，不能说动态已完成。工具没有运行光流或生成插帧就不能称流畅插帧。
