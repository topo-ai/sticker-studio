# 面部过渡与动作节拍

检查短循环的眼睛跳变、笑容瞬闪和动作峰值太短时加载本页。参数合格不等于表演自然；逐帧状态标注须来自实际图像。

## 分开决定动作、表情与循环

- 先辨别闭眼的作用：自然眨眼、持续笑眼、困倦垂眼、用力闭眼，或与动作无关的生成插帧。短动作无需强行添加一次眨眼；多条动画也无需同步闭眼。
- 眨眼需要睁眼→半闭→闭合→半开→睁眼；持续笑眼也需要进入与退出姿态。不要用淡入叠化两个眼形代替眼睑绘制，避免双重瞳孔和重影。
- 缺少中间姿态时定向生成或编辑眼睑，固定眼镜、眼角、瞳孔方向和原角色坐标。新增姿态应保留原动作中的手、道具与文字。局部合成后检查遮罩边缘与眼镜线条；受保护区域须保持一致。不能靠移动整个头部来对齐眼睑。
- 只修节奏时沿用原姿态；删去无意闭眼帧前检查相邻身体动作是否仍连贯。禁止把缺过渡解释为单纯帧率不足。

## 时间安排

逐条安排观察/预备、动作、表情峰值、恢复与循环停留。眼睑过渡可先试60–100ms、普通闭合约80–160ms，再结合画风与动作调整；这些是试作区间，不是生理标准或硬性平台要求。开心笑眼和困倦闭眼可持续更久。快跑等周期运动可使用等时帧且无需首尾停顿；打字保留手指速度，恳求或疲惫可增加峰值阅读时间。不要对全套乘同一个减速系数。

帧表格数与编码帧数独立。新增半闭眼姿态后总帧数可变化，各导出格式都使用同一时间轴；MP4固定帧率应按时间戳采样，不再按源序号平均分配。文字轨迹随原动作姿态映射，新增眼睑姿态沿用对应文字状态。

## 验收与记录

每帧记录`frame / eye_state / duration_ms / source_frame`，眼睛状态为`open / half / closed / occluded / not_applicable`。使用`scripts/timing_review.py PLAN.json`检查声明的状态链，包含末帧到首帧；脚本不识别图像，不证明眼睑画对了。

接触表检查全部眼睛状态，实际大小播放至少两个循环，分别看眼睑频率、闭眼停留、身体动作速度、文字阅读和接缝。新增姿态须检查是否出现双眼皮线、残留旧睫毛、眼镜变形或眼神漂移。记录逐条决定、实际时长、生成来源和修复前后文件哈希。重新编码后失效旧视觉结论并复查全部导出格式；不能沿用固定16帧、固定时长的旧检查器。
